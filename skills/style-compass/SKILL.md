# Style Compass 风格罗盘

## 概述

Style Compass 把"我觉得好看"转化为 Agent 能稳定执行的规范，并让**同一套审美跨介质成立**：不管最终产出是网页、应用 UI、PPT 还是平面设计，画面气质与品质基准一致。

> 核心信条一：**审美不是形容词，是可参数化的决定**。每条规范必须落到具体数值或明确的边界条件。
> 核心信条二：**规范与介质解耦**。风格文件只存"介质无关的视觉原语"（色彩比例、对比层级、留白占比、栅格性格、字体气质、材质语气）；落地成什么介质，通过 [介质映射](references/medium-mapping.md) 翻译成该介质的具体参数。这样一份风格库同时服务 PPT、网页、UI、平面，而不会写死在某一种画布上。

## 双模式总览

| 模式 | 触发场景 | 产物 |
| --- | --- | --- |
| **蒸馏模式（维护/进阶）** | 用户说"我收藏了这些好看的界面/图，帮我提炼风格规范" | 新增/更新 `references/style-*.md` |
| **应用模式（默认）** | 用户要求设计/实现某视觉产出（网页、UI、PPT、海报等） | 遵循规范产出的成品（代码/画布/文案方案） |

## 一、蒸馏模式：把案例蒸馏成介质无关的风格

仅当用户提供案例并要求提炼时执行。**蒸馏时一律剥离介质外壳、只留可迁移的视觉本质**——一张好海报教会你的应是"大字号 + 大留白的对比节奏"，而不是"海报尺寸"。

1. **逐张标注**：每个案例复制一份 [案例标注模板](references/case-card-template.md)，区分"可迁移要素（视觉原语）"与"介质特有要素"。
2. **聚类**：按"视觉气质"归类（"编辑杂志感""贵气克制""暗色科技"是气质；"三个 SaaS 官网"不是）。
3. **每簇产出一份风格文件**：用 [风格规范模板](references/style-template.md) 生成 `references/style-<气质名>.md`，全部字段用**比例/区间/气质**表述，禁止写死介质参数。
4. **验证**：拿该风格分别"脑内渲染"一个网页和一个 PPT/海报，确认气质在两个介质都成立；过一遍 [AI 味反模式清单](references/ai-tells.md)。

## 二、应用模式：跨介质默认工作流

按顺序执行，不要跳过任何一步。

### 第 1 步：识别介质与任务

先明确三件事：**产出介质**（网页 / 应用 UI / PPT 演示 / 平面海报 / 其他）、**受众与情绪目标**、**内容规模**。介质决定后面用 [介质映射](references/medium-mapping.md) 的哪一章翻译规范。

### 第 2 步：锁定风格

- 在 `references/` 中挑选最匹配的 `style-*.md`；若无匹配，先与用户确认方向或速配最接近的气质。
- 若用户点名某风格或"像这张图"，直接锁定并回到蒸馏模式补一页案例卡。

### 第 3 步：提取设计 token（介质无关层）

从风格文件提取一套 token，这是整个产出的"宪法"：

- **色板**：背景/表面/文字/强调四层色值 + 使用比例 + 禁用色相。
- **对比节奏**：字号阶梯的比例关系（如 显示:标题:正文 ≈ 3.5:2:1）、文字的轻重强弱排序。
- **留白纪律**：区块间距比例、内容密度目标、关键信息周边留白的最低要求。
- **栅格性格**：对齐方式（对称/非对称/杂志错落）、模块排布逻辑。
- **字体气质与边界**：衬线/无衬线/等宽的选用逻辑、字距行高的档位。
- **材质与语气**：圆角曲率、线条/阴影的有无与分寸、图标/图像风格。

### 第 4 步：介质落地（翻译层）

打开 [介质映射](references/medium-mapping.md)，读**对应介质那一章**，把第 3 步的 token 翻译成该介质的具体参数：

- **画布与单位**：网页断点 / UI pt-dp / PPT 16:9 或 4:3 / 平面出血与分辨率。
- **字体可用性**：该介质能安全用什么字体、需要嵌入还是系统回退。
- **颜色模型**：屏幕 RGB vs 印刷 CMYK（如平面涉及印刷）。
- **安全区与栅格**：PPT 边距、网页容器宽度、印刷出血线。
- **该介质特有的质量坑**（如 PPT 的满屏文字、印刷的对比度损失）。

同一套 token 落到 PPT 就是"留白 30%、大标题 60pt、对齐到 12 列栅格"，落到网页就是相应的 CSS 实现，气质一致、参数不同。

### 第 5 步：全局底线（所有风格、所有介质通用）

- **不做半成品**：交互介质必须给 hover/active、载入、空、错误四态；静态画面必须有明确视觉焦点与阅读顺序。
- **反 AI 味**：产出后逐条核对 [AI 味反模式清单](references/ai-tells.md)。
- **内容具体**：禁止 "Acme / John Doe / Lorem / 99.99%" 一类占位内容，写贴合场景的真实感文案数据。
- **对比与可读性**：正文与背景对比度达标；弱对比只允许用于装饰层。
- **拒绝廉价效果**：默认禁用发光、纯黑 `#000`、过饱和撞色、无意义的渐变。
- **技术栈约束（仅代码类产出）**：先查 `package.json` 再引第三方库；不假设库存在。

### 第 6 步：自检与交付

对照风格文件的"自检清单" + 介质映射章节的"交付检查"，逐项打勾；代码类产出还要跑通构建或至少静态自查，再交付。

## 资源目录说明

- `references/`：风格库 + 模板 + 介质映射（上面已述）。
- `assets/`：不进入上下文的素材——参考图、字体授权清单、before/after 对比等。
- `research/`（仓库级）：提炼方法论、介质无关性的设计依据，开源后供社区阅读。
